## User correction and reproduced root cause

The exact failing message was:

> 【京东】https://3.jd.hk/104-oHdd 「港版Switch2国际多语言」 点击链接直接打开

The v1.3.0 parser was registered and enabled, but `can_parse` returned
false, extraction returned `[]`, and ParserManager found no links. The
short host `3.jd.hk` and target host `mitem.jd.hk` were both missing, so the
message never reached parsing or emoji feedback. This is a verified code
defect; the user's installed version/runtime is not independently observed.

The real short link returned HTTP302 to the numeric mobile item URL for
SKU10235967540747. Its selected variant is the Zelda limited Switch2,
not every variant represented by the generic share title. The fixed parser
uses the target SKU's complete product title and images.

## Implemented behavior

- Recognize `3.jd.hk`, `mitem.jd.hk`, `item.jd.hk` using exact trusted hosts;
  retain URL credentials/port checks and document navigation interception.
- Read JSON-valued root properties from `_itemOnly` / `_itemInfo` without
  evaluating JS, including the root object's actual trailing comma.
- Check item/product/URL SKU equality before extracting mobile facts.
  Other variants and recommendations never supply the selected price/image.
- When a numeric PC page has no product data, request the same SKU's
  official mobile URL before browser fallback.
- Take public decimal `priceFloor.ext.jdPrice` or `priceFloor.price` only
  when the response does not require login. Never reverse font encoding or
  masks, infer from tax, or substitute original/recommendation prices.
- User changed GitHub behavior: ordinary links automatically fetch bounded
  source and images, send the existing information card, then optional AI
  summary. No quoted detail command or long README/comment/patch output.
  Archive retains source; permissions, proxy options, output modes, token
  isolation, model cache and AI deadline continue to apply.
- Skip unsupported SVGs and known badge/stat/sponsor widgets discovered
  in the real AstrBot README, so automatic image output selects content.

| https://mitem.jd.hk/product/10160071768695.html | 0.38s; correct international multilingual Switch2 variant, cover and 3 main images |

Independent low-frequency research captured one anonymous response for
SKU10235967540747 with `priceFloor.ext.jdPrice=3689.00`, `urgeLogin=false`.
The implemented parser reproduced ¥3689.00 from that saved real response,
with the same exact SKU/title and 9 main images. A fresh request reverted
to masks; this is not a stable anonymous-price guarantee and the evidence
does not establish tracking parameters as the cause.

The captured price is a CNY product reference price for the page's default
Beijing region. The page separately listed estimated import tax ¥335.70;
it is not a guaranteed final tax-inclusive checkout amount. No order or
checkout operation occurred.

A later fresh request of the same share redirected from the item page to
the actual `cfe.m.jd.com/privatedomain/risk_handler/` endpoint. The parser
does not follow this navigation or retry it in a browser; it explicitly
reports that login/manual verification is required. Prior real success
proves the extraction path, not stable anonymous availability.

- https://www.8bitdo.cn/micro/ → https://detail.tmall.com/item.htm?id=733931977298
- https://www.8bitdo.cn/lite-se/ → https://detail.tmall.com/item.htm?id=679116107735

Actual first-party scripts referenced getdetail/6.0, detail.data.get/1.0
and getdesc/7.0. Fresh anonymous calls returned x5referer risk JS or
`RGV587_ERROR::SM` login data, without an anonymous `_m_h5_tk` token or
server-verified product fields. Isolated guest Edge DOMs contained login
iframes; Edge's nonzero exits are recorded as a browser-validation limit.
No existing browser profile, logged-in Cookie or manual verification was used.

Ruling: keep Taobao deferred under the approved live-success gate. These
two samples/current environment do not prove every Taobao product always
requires login. Cost: no Taobao parser in this patch, no fabricated success.
