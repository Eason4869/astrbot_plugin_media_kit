# 抖音解析与卡片边界修复

基线：`dev` 的 `c9917ed`（1.2.0-beta）。用户确认接受普通 HTTP 解析遇到风控后的本机 Chromium/Chrome/Edge 回退。

## 方案与约束

- 仅增加 HTTP 重试无法恢复验证码页；手工构造新签名的网络验证未获自动审批，未执行。
- 采用已实测取得目标数据的正常浏览器会话：打开固定抖音作品页，观察站点自身发出的详情响应，校验作品 ID 后沿用现有媒体字段提取。
- 使用现有 aiohttp 连接本机 CDP，不增加 Python 依赖。自动寻找浏览器，可指定可执行文件或关闭回退；Linux 需要安装 Chromium，并满足浏览器沙箱运行条件。
- 每次使用独立临时访客目录，串行启动，整个操作最多 30 秒。正常结束、错误和取消都关闭浏览器并清理目录。不读取用户浏览器配置，不自动操作人工验证码，不添加规避浏览器检测的启动参数。
- 分享页缺少作品数据时最多请求三次；识别验证码后立即转浏览器，避免继续重复请求验证码页。
- 四布局移除主体底边下面的额外 14 像素阴影区，样式缓存失效。
- 用户指定版本更新为 `1.2.1`，文档记录部署要求与仍可能需要人工验证的限制。

## 验证

完整单测与原有 beta 功能不回归；覆盖错误作品 ID、浏览器缺失、取消和超时资源清理、无回退时的正常路径、卡片深浅主题和有无封面。实际使用用户短链验证目标作者、标题和媒体，并读取视频文件前缀确认可下载。
